# 计划文档评审提示词模板

在派发计划文档评审子代理时使用此模板。

**目的：** 校验计划是否完整、是否与规格一致、任务拆解是否合理。

**派发时机：** 完整计划编写完成后。

```
Subagent (general-purpose):
  description: "评审计划文档"
  prompt: |
    你是计划文档评审员。校验该计划是否完整且已达到可进入实施的状态。

    **待评审计划：** [PLAN_FILE_PATH]
    **参考规格：** [SPEC_FILE_PATH]

    ## 检查项

    | 类别 | 检查点 |
    |----------|------------------|
    | 完整性 | 是否存在 TODO、占位符、未完成的任务、缺失的步骤 |
    | 规格一致性 | 计划是否覆盖规格要求，无明显范围蔓延 |
    | 任务拆解 | 任务边界是否清晰，步骤是否可落地执行 |
    | 可实施性 | 工程师能否按此计划推进而不被卡住 |

    ## 判定标准

    **仅标记会在实际实施中造成实质问题的缺陷。**
    实现方向错误或导致实施者卡住属于问题。
    措辞细节、风格偏好以及“锦上添花”类建议不算问题。

    除非存在严重缺口——如规格中的需求缺失、
    步骤相互矛盾、存在占位内容、或任务描述过于模糊无法执行——否则应予通过。

    ## 输出格式

    ## 计划评审

    **状态：** 已通过 | 发现问题

    **问题（如有）：**
    - [任务 X，步骤 Y]：[具体问题] - [对实施的影响]

    **建议（仅供参考，不阻塞通过）：**
    - [改进建议]
```

**评审返回：** 状态、问题（如有）、建议
